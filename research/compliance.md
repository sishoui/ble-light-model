# 发布合规要求研究报告（ticket #5）

> 项目：微信小程序通过 BLE 控制 ESP32-C3（驱动 8 路 WS2812 灯带）
> 场景：vibecoding，测试流程 PC 闭环，真机仅 Android 低频冒烟
> 调研日期：2026-11-19
> 来源：wayfinder 地图 #1 的 research ticket #5 解决产出
> 说明：凡属需用户/后台二次确认的点均单列标注（见文末第 6 节）。

---

## 0. 一页结论（TL;DR）

1. **普通 BLE GATT（wx.openBluetoothAdapter / wx.createBLEConnection / wx.writeBLECharacteristicValue 等）本身不需要走"硬件设备接入/model_id"那套**，也不强制企业认证。只要**隐私指引里勾选"访问你的蓝牙"**即可调用，这是本项目的可行主路径。
2. **"硬件设备接入"（model_id / 设备消息 / WMPF）是给需要「微信向用户推送设备消息」「设备认证」的场景用的**，且开通前置是 **微信认证（个人主体无法认证）**——本项目不需要，不建议走。
3. **真正的分水岭是主体类型**：个人主体**无法做微信认证**，也**无法开通"硬件设备接入/设备消息"**；若坚持用个人主体，只能走"纯 GATT 工具类"，且**类目选择上"工具-设备管理"大概率不对个人开放**（需后台实测），要退而用"工具-效率"等并如实描述。
4. 若要稳妥、可持续（尤其想上"设备管理"类目、想要设备消息、想以后扩展），**推荐企业/个体工商户主体 + 微信认证**。
5. **备案（2023 起强制）**：个人主体备身份证+人脸核验；企业主体备营业执照+法人证件+对公/法人核验。未备案无法上架。
6. 隐私弹窗必须接 `wx.onNeedPrivacyAuthorization` + `wx.requirePrivacyAuthorize` + 自定义弹窗（同意按钮用 `open-type="agreePrivacyAuthorization"`），否则蓝牙接口返回 errno:112 / 104。
7. 审核时效：官方 1–7 个工作日（通常 3 天内），每主体每年可加急 2 次；工具类不涉及二次人工复核，通常较快。

## 1. 主体类型影响与建议

### 1.1 个人主体 vs 企业主体：对 BLE 小程序的核心差异

| 维度 | 个人主体 | 企业 / 个体工商户主体 |
|---|---|---|
| 微信认证 | **不支持**（个人主体无法微信认证） | 可申请（企业按需，个体户 ¥30/年 限时优惠，约 1–3 工作日） |
| 微信支付 / 虚拟支付 | 无（虚拟支付正在有条件向个人开放，但需符合类目） | 可用 |
| 获取用户手机号 getPhoneNumber | 不可用 | 可用（需认证） |
| **开通「硬件设备接入 / 设备消息 / model_id」** | **不可用**（前置要求微信认证） | 可用 |
| 可选服务类目 | 仅"低风险、非盈利、工具化"类目 | 类目范围广，可覆盖交易/服务/硬件 |
| **纯 BLE GATT 调用**（wx.openBluetoothAdapter 等） | **可用**（只需隐私声明"访问你的蓝牙"） | 可用 |
| 备案材料 | 本人身份证 + 人脸核验 | 营业执照 + 法人证件 + 对公/法人核验 |
| 适合场景 | 纯工具、内容展示、本地控制、个人自用 | 商用、设备管理、需推送/交易 |

**结论**：**"个人主体能不能做 BLE 设备控制类小程序"——能，但仅限"纯 GATT 直连控制"这一条窄路，且不带"设备消息/设备管理"能力。** 想上"工具-设备管理"类目、想要设备消息、想长期商用，就必须企业/个体户主体 + 微信认证。

### 1.2 个人主体的"变通路径"与边界

- **纯 GATT 工具路线**：不碰 model_id、不碰设备消息，只做"搜索→连接→读写特征值"。类目可退而选"工具-效率""工具-图片/视频编辑"等个人开放类目，功能描述如实写"通过蓝牙连接并控制 LED 灯带"。
- **不可行/受限**：
  - 无法开通"硬件设备接入"（微信认证前置不满足）。
  - 无法选"社交/电商/交易/设备管理（如需认证的子项）"等类目。
  - 触到"超范围经营 / 类目不符"最易被拒（运营规范 1.2）。
- **变通风险提示**：个人主体做设备控制，审核员可能以"类目与实际功能不符"或"未开放服务内容"打回（参考真实拒因）。若打回，多数只能改类目/改描述，或被要求换主体。**换主体成本极高（AppID 主体迁移困难，往往等于重做）**，因此**主体类型必须在第一步就定死**。

### 1.3 建议

- **首选**：企业 / 个体工商户主体 + 微信认证 + "工具-设备管理"类目 + 备案 → 最稳，可扩展设备消息。
- **次选（个人自用/极客项目）**：个人主体 + 纯 GATT + "工具-效率/其他工具"类目 + 备案 + 隐私指引声明蓝牙 → 能上线，但功能与类目受限，且不要期待"设备管理"能力。
- **关键提醒**：若打算长期运营或给别人用，不要图省事用个人主体注册——**后期迁主体几乎等于重开**。

## 2. 隐私协议接入 checklist（从注册到发版）

### 2.1 前置：后台声明《用户隐私保护指引》

- 路径：小程序管理后台 → 设置 → 基本设置 → 服务内容声明 → 用户隐私保护指引。
- **必须勾选"访问你的蓝牙"**。微信对隐私接口与处理信息的映射：
  - **访问你的蓝牙**：`wx.authorize({scope:'scope.bluetooth'})`、`wx.openBluetoothAdapter`、`wx.createBLEPeripheralServer`（以及 BLE 扫描/连接/读写系列）。
- 填写申请理由 + 联系方式（供用户行使查阅/复制/更正/删除权利）。
- 每次修改隐私指引都会触发一次审核（约 1 小时–数小时）。
- **未声明后果**：`openBluetoothAdapter` 返回 `errno:112`（api scope is not declared in the privacy agreement）；提审时若勾"未采集隐私"还会导致接口被回收（errno:1025 类）。

### 2.2 代码接入（推荐"按需触发"方案）

原理流程：
`wx.requirePrivacyAuthorize` → 触发 `wx.onNeedPrivacyAuthorization` 事件 → 自定义弹窗 → 用户点"同意/拒绝" → 调用 `resolve({event, buttonId})` → 继续/终止 → 再调用蓝牙接口。

关键 API：
- `wx.getPrivacySetting`：查用户是否已同意隐私协议（启动时判断）。
- `wx.onNeedPrivacyAuthorization`：监听需要授权的事件（**只在 app 启动注册一次**）。
- `wx.requirePrivacyAuthorize`：在调用真实隐私接口前主动触发授权。
- `wx.openPrivacyContract`：打开隐私协议全文页。
- 同意按钮：`open-type="agreePrivacyAuthorization"` + `bind:agreeprivacyauthorization`。

最小可用骨架（参考官方/社区实践，需按项目框架落地）：

```javascript
// app.js onLaunch：只注册一次
if (wx.onNeedPrivacyAuthorization) {
  wx.onNeedPrivacyAuthorization((resolve) => {
    // 弹出你的自定义弹窗，用户选择后：
    resolve({ event: 'agree', buttonId: 'agree-btn' });    // 同意
    // resolve({ event: 'disagree', buttonId: 'disagree-btn' }); // 拒绝
  });
}
```

```javascript
// 调用蓝牙前先确保授权
async function ensurePrivacy() {
  if (typeof wx.requirePrivacyAuthorize !== 'function') return true; // 低版本无此 API，视为已授权
  try {
    await wx.requirePrivacyAuthorize();
    return true;              // 同意
  } catch (e) {
    return false;             // 拒绝 / errno 104
  }
}

// 业务里
if (!(await ensurePrivacy())) { wx.showToast({ title: '需同意隐私指引后才能连接设备' }); return; }
wx.openBluetoothAdapter({ /* ... */ });
```

同意按钮 WXML 规范：

```html
<button id="agree-btn" open-type="agreePrivacyAuthorization"
        bind:agreeprivacyauthorization="onAgree">同意</button>
<button id="disagree-btn" bind:tap="onDisagree">不同意</button>
```

### 2.3 隐私弹窗 UI 规范

- 必须**先告知后采集**：说明收集什么（蓝牙/设备信息）、用途（连接并控制灯带）、存储与删除方式。
- 弹窗需在用户**主动触发动作**时弹出（如点"连接设备"），不要一启动就强制弹（推荐按需触发方案，体验更好、也更易过审）。
- 拒绝后要给出明确提示与兜底（如禁用连接按钮 + 文案）。
- 注意：用户拒绝后**有 10 秒冷却**，10 秒内再次调用不会弹；需给用户提示语。
- 隐私协议全文入口用 `wx.openPrivacyContract` 可打开，建议页面内也放《隐私政策》可随时查看。

### 2.4 app.json 声明

- `app.json` 的 `permission` 中声明 `scope.bluetooth` 的 `desc`（用途说明，便于审核与用户理解）：
  ```json
  "permission": {
    "scope.bluetooth": { "desc": "你的蓝牙信息将用于连接并控制 LED 灯带设备" }
  }
  ```

### 2.5 提审前自检

- [ ] 隐私指引已勾"访问你的蓝牙"，且已审核通过。
- [ ] 已接 `wx.onNeedPrivacyAuthorization` + `wx.requirePrivacyAuthorize`，低版本有 `typeof` 兜底。
- [ ] 同意按钮用了 `open-type="agreePrivacyAuthorization"`。
- [ ] 无登录也能浏览核心界面（审核员不注册账号）。
- [ ] 无空页面/占位文案/测试数据。
- [ ] 提审时"是否采集隐私"如实勾选（采集蓝牙即勾"是"，不要勾"否"）。

## 3. 硬件设备接入评估

### 3.1 它是什么、给谁用

"硬件设备接入"是微信给**需要把设备纳入微信设备体系**的场景准备的能力：注册设备拿 `model_id`，进而使用「设备消息（向用户推送服务通知）」「设备认证」「WMPF 硬件框架」等。

接入流程（官方《硬件能力接入流程》）：
1. 申请"工具-设备管理"类目（无需资质）。
2. 后台 功能 → 硬件设备 → 开通（管理员扫码）。
3. 添加硬件设备（**需审核**，如实填写设备信息）。
4. 审核通过后拿到 `model_id`。
5. 申请"设备能力"（需审核，如设备消息）。

### 3.2 门槛

- **前置：需微信认证**（腾讯云文档明确"完成微信认证是开通设备管理的必要操作"）→ **个人主体无法开通**。
- 需提交真实设备信息、审核设备真实性。
- 设备消息模板需在公共模板库选或申请，字段/枚举受限。
- 整套偏"设备厂商 + 商用"定位，个人/玩具项目成本高。

### 3.3 本项目是否需要？——不需要

本项目只用 **BLE GATT 直连**（wx.createBLEConnection / getBLEDeviceServices / getBLEDeviceCharacteristics / writeBLECharacteristicValue / notifyBLECharacteristicValueChange）。这套**不依赖 model_id，也不要求"设备消息"**。灯带控制是"小程序↔手机↔设备"点对点，不需要微信向用户推送服务通知。

### 3.4 走/不走的利弊

| | 走「硬件设备接入/model_id」 | 不走（纯 GATT） |
|---|---|---|
| 前置门槛 | 需微信认证、设备审核 | 只需隐私声明蓝牙 |
| 主体要求 | 企业/个体户 | 个人亦可 |
| 能力 | 可用设备消息推送、设备认证、WMPF | 仅点对点控制 |
| 本项目适配 | 用不上、徒增成本 | ✅ 完全够用 |
| 审核复杂度 | 设备审核 + 能力审核 | 仅常规审核 |
| 建议 | ❌ 不建议 | ✅ **推荐** |

**结论**：本项目走**纯 BLE GATT**，按"工具"类目申报，不走硬件设备接入那套。唯一保留：若以后想加"设备离线/耗材提醒"等主动推送，再补设备接入。

## 4. 小程序备案要求

### 4.1 背景与时限

- 依据工信部要求，小程序同 App/网站一样需 ICP 备案。
- 2023-09-01 起：**新小程序须完成备案后才可上架**；已上架的须于 **2024-03-31 前**完成备案，否则 2024-04-01 起清退。

### 4.2 备案流程（5 环节）

1. 备案信息填写（主体信息、小程序信息、服务类目、负责人信息）。
2. 平台初审（1–2 个工作日）。
3. 工信部短信核验。
4. 通管局审核。
5. 备案成功，获得备案号。

### 4.3 材料

| 主体 | 所需材料 |
|---|---|
| **个人主体** | 本人**身份证正反面**照片；本人手机号；**人脸核验**（负责人须为小程序主体本人）；小程序名称/简介/服务类目 |
| **企业主体** | **营业执照**；**法人身份证**；管理员手机号；法人/管理员人脸核验；部分地区需对公账户打款核验或授权书（如上海自动生成授权书） |

补充规则：
- 证件有效期自提交起应 **> 3 个月**（宁夏需 > 6 个月）。
- 服务类目必须与小程序实际功能一致（类目不符是备案驳回高发原因）。
- 简介/服务内容描述要具体，避免"提供互联网信息服务"这类笼统表述。

### 4.4 BLE 类小程序备案要点

- 备案本身**没有专门的"蓝牙"材料**，关键在：主体证件 + 类目一致 + 服务内容如实描述（如"蓝牙连接控制 LED 灯带的工具"）。
- 若走"工具-设备管理"类目，需企业/个体户主体；个人主体按"工具-其他工具/效率"如实备案。
- 备案与微信认证相互独立：个人主体可备案但不能认证；企业主体通常"认证+备案"一起做。

## 5. 审核实操指南

### 5.1 提交流程

开发版 → 上传 → 后台"版本管理"设为审核版 → 填审核信息（功能页面、测试账号如有、类目）→ 提交审核 → 通过后"发布"。

### 5.2 常见拒因与规避

| 拒因（运营规范） | 含义 | 本项目规避方法 |
|---|---|---|
| **1.2 / 2.1 类目不符 / 未开放服务内容** | 选了与实际不符或不对主体开放的类目 | 类目如实选；个人主体不碰"设备管理/社交/交易"；功能描述不超范围 |
| **2.2 功能不完整** | 页面空白、死链、占位、无法体验 | 核心功能不登录可体验；无测试数据/占位文案；真机可用的 BLE 流程可演示 |
| **2.3 / 3.4 隐私未告知** | 调用蓝牙未在隐私指引声明、无弹窗 | 勾"访问你的蓝牙"+ 接隐私弹窗（见第 2 节） |
| **3.2 诱导分享** | 强制分享/关注才可用 | 不做强制分享/关注解锁 |
| 类目与实际功能不符 | 简介/页面出现超类目内容 | 简介只写类目内能力，不出现交易/社交等词 |

### 5.3 提审前自查清单（针对本项目）

- [ ] 类目 = 实际功能（工具类；个人主体用个人可开类目）。
- [ ] 隐私指引勾"访问你的蓝牙"且已通过。
- [ ] 隐私弹窗接好（requirePrivacyAuthorize + onNeedPrivacyAuthorization + 同意按钮规范）。
- [ ] 首页/核心页无需登录即可看到（审核员不注册）。
- [ ] 无空页/占位/测试数据；蓝牙搜索、连接、控制流程可走通（录屏/真机兜底）。
- [ ] 无强制分享/关注。
- [ ] 名称、简介、类目、页面内容一致。
- [ ] 备案已完成（未备案无法上架）。
- [ ] （企业）微信认证已完成（如需设备管理能力）。

### 5.4 审核时长

- 官方规则：**1–7 个工作日内**完成，通常 **3 天内**出结果，快的几分钟。
- 工具类一般**不涉及属地网信二次复核**（二次复核多见于时政/社交/文娱类，约 7 天甚至更久，且不可加急）。
- **加急**：每主体每年可加急 2 次，提交审核页勾选"加急"。
- 可随时撤回修改后重提。

## 6. 需用户确认的事项

> 以下事项直接影响主体/类目/工作量，**请在动手开发/提审前由用户确认**。

1. **主体类型（最关键）**：个人 / 企业 / 个体工商户？
   - 选个人 → 只能走纯 GATT + 个人可开类目，无法设备管理/微信认证，长期扩展受限。
   - 选企业/个体户 → 可认证、可选"设备管理"类目、可扩展设备消息，推荐。
2. **是否已有微信认证？**（个人主体无法认证；企业主体需先认证才能用设备管理相关能力）。
3. **是否已有小程序 AppID？主体是否已定死？**（主体迁移成本高，等于重开，务必先定）。
4. **服务类目以哪套为准**：是否在后台实测过"工具-设备管理"对个人主体是否可选？（事实底稿标注为"非个人主体"，需后台确认；个人主体大概率只能退选"工具-效率/其他工具"）。
5. **是否需要"设备消息推送"能力**（如灯带离线提醒）？需要则必须企业主体 + 微信认证 + 走硬件设备接入；不需要则纯 GATT 即可。
6. **是否涉及任何交易/付费**（如付费解锁灯效）？涉及则需企业主体 + 微信支付，个人主体不可做。
7. **目标用户与平台范围**：仅 Android 真机冒烟，还是要覆盖 iOS？（BLE 在 iOS/Android 均有差异，审核演示设备需匹配）。
8. **备案进度**：是否已完成备案？未备案无法上架。
9. **隐私政策文本**：是否已有可公示的《隐私政策》全文（弹窗里要能打开）。
